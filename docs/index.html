How an edition is made

The same pipeline runs every two weeks. Each stage is written down as an instruction file in the repository, so anyone can rerun it, criticise it or improve it.

  1. Harvest

    About 200 sources in 18 languages are collected continuously: news agencies, ministries, state and exile media, GDELT and primary data such as IMF PortWatch transits.

  2. Facts from three sides

    Every key event is sourced from a Western outlet, the actor's own side and a third party. Missing perspectives are recorded as gaps, not filled in.

  3. Analysis

    Key assumptions, competing hypotheses and warning indicators. Facts, assessments and forecasts are kept apart.

  4. Three blind lenses

    Great-power strategy, base rates and domestic constraints each forecast every question in a separate session, without seeing each other.

  5. Red team

    A fourth session attacks the analysis and may adjust a forecast by at most 15 points, only with evidence.

  6. Freeze

    The official forecast is committed to an append-only registry. Git history is the proof that nothing was edited later. Only then are prediction markets consulted for comparison.

  7. Score

    When questions resolve, Brier scores are computed against a status-quo baseline and the crowd, including the misses.

What makes it different

Geopolitical commentary is plentiful. Commentary that can be wrong in public, and is measured when it is, is rare.

Pre-registered

Probabilities from 1% to 99%, written to a registry that is never edited, with dated resolution criteria and sources fixed in advance.

Three perspectives per event

A statement from Moscow, Washington, Beijing or Tehran is recorded as a fact about a statement, never as proof that the event happened.

Measured against baselines

Accuracy is compared with "nothing changes" and with forecasting crowds. No conclusions are drawn before 30 resolved questions.

Open by default

Methodology, prompts, code, forecasts and reports are public. Code under MIT, content under CC BY 4.0.

Versioned

Every report states the framework version, methodology version and AI models that produced it, so improvements can be told apart from luck.

Honest about its limits

This is an experiment run by one person with AI assistance. It is not a newsroom, a think tank or a trading signal.

Track record

Scoring uses the Brier score: the mean squared difference between forecast and outcome. 0 is perfect; always answering 50% scores 0.25.

17 questions resolved. Brier score of the official forecast: 0.117 against 0.302 for "nothing changes" (skill +0.61, indicative).

Lower is better. A positive skill score means the forecasts beat the status-quo baseline. Full breakdown by lens, vector and horizon: the latest 01_scores.md.

Contribute

The project improves through criticism. The most useful help is specific: a better source, a flawed assumption, a bug.

  • Sources in your language. Official, state, independent or exile outlets the harvester is missing, especially from the actors' own side.
  • Challenge a forecast. Open an issue with the evidence. It is weighed in the next edition; frozen forecasts are never changed.
  • Review the method. Lenses, aggregation and scoring are open for the quarterly review.
  • Code. The harvester and scoring tools are small, standard-library Python.
